# 思考链

把当前任务的思考过程显示成右侧边栏里一棵实时更新的树，同时把它落到磁盘上的 Markdown 文件里，让人和 agent 看同一份东西。

## 这个插件提供什么

- **窗口右边缘的按钮。** 点一下就在右侧弹出侧边栏并切到思考链标签页；这个标签页也出现在侧边栏的引导页里，可以从那里打开。
- **三层结构。** 用深度分层：最上面一个根节点是**目标**，它的子节点是**路线**（要做什么、下载什么、用什么库或模型实现、技术路线、风格取向），再下一层是具体到**做什么怎么做**的步骤（命令、文件、接口、顺序）。
- **实时更新。** 面板打开时每 1.5 秒左右重新读一次文件夹，agent 边想边写，面板跟着变。正在编辑某个节点时暂停刷新，保存或取消后恢复。
- **改动能留住。** 正文在面板里用 Markdown 编辑，保存直接写回文件；状态点是"待办 → 进行中 → 完成 → 受阻"循环；加子节点、删节点（连同它的子节点）也是直接改文件夹。
- **附带一个技能** `thinking-tree`，告诉 agent 文件夹契约、什么时候建树、做的过程中怎么持续更新，以及**用户的修改优先于它自己记忆里的方案**。

## 磁盘上的样子

所有节点都放在当前会话工作区里的同一个文件夹：

```
thinking-tree/
├── 00-goal.md
├── 01-tech-route.md
├── 01-1-write-host-route.md
└── 02-visual-style.md
```

**一个块就是一个 `.md` 文件**，全部平铺在这个文件夹里，front matter 承载结构：

```markdown
---
id: 01-tech-route
parent: 00-goal
order: 1
title: 技术路线
status: active
updated: 2026-01-01T00:00:00.000Z
---

正文用 Markdown 写。
```

树的结构**只由 `parent` 决定**，文件名只是方便人看。以 `_` 开头的文件会被面板忽略，可以放给人看的说明。

## 怎么用

1. 提一个多步骤的任务。agent 会建出 `thinking-tree/`，把目标、路线、步骤写进去。
2. 点右边缘的按钮打开面板，看它一边做一边长。
3. 想改路线就直接在面板里改、保存，然后让 agent 继续。它动手前会重读文件夹，按你改的做。

## 限制

- 树绑定在会话的工作区目录上；解析不出工作区的会话会显示空面板。
- 面板只渲染 Markdown 的一个子集（标题、列表、行内代码与代码块、引用、强调、链接），不渲染表格、图片和原始 HTML。
- 树不在会话日志里，它就是工作区里的文件；分叉出来的会话共用同一个文件夹。
- 期望只有一个目标节点；多出来的根节点会作为额外的顶层卡片显示，不会被合并。
